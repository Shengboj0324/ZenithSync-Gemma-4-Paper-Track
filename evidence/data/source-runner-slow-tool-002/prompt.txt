Problem Statement:
**Title:** HTTPException Initialization Without Override Results in Invalid 'None None' Status

**Description:**
When initializing a top-level `HTTPException` without properly overriding it in a subclass, Pyramid attempts to create a `Response` object with an invalid status `'None None'`. This change in behavior is due to stricter status code validation in WebOb versions >=1.5.0, which now rejects such invalid statuses.

**Example Buggy Code:**
```python
from pyramid.httpexceptions import HTTPException

# Initializing HTTPException without overriding status
exc = HTTPException('message')
print(exc.status)  # Outputs: 'None None'
```

**Expected Behavior:**
A valid `HTTPException` should have a proper status code. If not overridden in a subclass, it should default to a standard error status like `'520 Unknown Error'` to ensure compatibility and prevent invalid status values.

**Actual Behavior:**
Initializing `HTTPException` without overriding leads to a `Response` with status `'None None'`, causing a `ValueError` due to invalid status code formatting.

**Error Message:**
```
ValueError: Invalid status code, integer required.
```
