# P1 implementation and evidence

Updated October 8, 2026. P1 remains in progress. The Pod has not been started by this implementation work.

## Checkpoint storage gate

Implemented CPU-only bounded safetensors inspection in `zenithsync/model_intake.py`, with adversarial tests and a repeatable evidence runner in `scripts/verify_model_storage.py`. The storage contract follows the upstream [safetensors format](https://github.com/safetensors/safetensors#format), restricted explicitly to supported byte-aligned dtypes. The downloaded W4 checkpoint stores packed integers; the validator does not treat the logical four-bit weights as ordinary floating-point tensors.

For every tensor, the validator checks that interval length equals dtype byte width multiplied by the product of dimensions, using exact integer arithmetic. Ordered intervals must meet exactly, starting at zero and ending at the data-buffer length. This establishes complete coverage without overlap, including explicit handling of empty tensors. Duplicate JSON keys, invalid dimensions, excessive headers, symlinks and observed concurrent file changes are rejected. This is an owned, quiescent-directory check, not a security boundary against hostile concurrent filesystem mutation.

[Storage receipt](../evidence/p1/storage-001/receipt.json) and [test log](../evidence/p1/storage-001/tests.log) record a successful full-file rehash against the existing eight-file model manifest and structural inspection of the actual downloaded checkpoint. All 33 current tests passed, including seven new storage tests with multiple malformed cases. Source identities are included in the receipt.

The checkpoint contains 2,009 tensor descriptors and 23,265,352,448 bytes. Numerical weight values, publisher authenticity, full architecture/configuration correspondence, tokenizer behavior, GPU loader support, inference quality and training compatibility are not established by this gate. Passing storage inspection must never be reported as an error-free or training-ready model.

## R2 transport gate

Implemented `zenithsync/object_store.py`: explicitly curated artifacts are stored under SHA-256 content keys. Publication verifies the local manifest, uploads missing objects, streams remote bytes back through SHA-256, rechecks the source and then publishes the manifest. An existing corrupt object is rejected rather than silently overwritten. Retries reuse whole verified objects. Restoration enforces an explicit byte budget and stages files privately before exposing a completely verified bundle at a new destination. Existing destinations and known credential paths are rejected.

The [live R2 receipt](../evidence/p1/r2-transport-001/receipt.json) records successful upload, readback, repeat publication and restore of 10,485,777 synthetic bytes across two files. The nonempty file used the SDK's multipart path; the other file exercised zero-byte handling. Both objects were reused on the second publication. The [40-test log](../evidence/p1/r2-transport-001/tests.log) includes fault-injected corruption, source drift, denied access, credential-path exclusion, byte-budget and existing-destination checks. This live test does not prove bulk checkpoint transfer or Runpod restoration.

Transport uses [R2's S3-compatible API](https://developers.cloudflare.com/r2/api/s3/api/) and [Boto3 managed upload](https://docs.aws.amazon.com/boto3/latest/reference/services/s3/client/upload_file.html). The live runner limits multipart concurrency to two and uses bounded SDK retries and network timeouts. The implementation does not mistake ETags for SHA-256. Readback incurs an additional full object download; that cost is intentional at the integrity gate.

Limitations: trusted manifests and owned quiescent local directories are required. Content addressing is not an access-control boundary or cryptographic publisher authentication. A hard process kill can leave incomplete multipart uploads, so production cleanup policy remains pending. Partial whole objects are not resumed across processes. Local atomic rename provides visibility semantics, not a power-loss durability guarantee. Credential filename exclusion is not a comprehensive secret scanner; callers must select curated bundles. The fixture objects are retained in `verification/p1/transport-v1`, separate from future model/data objects.
